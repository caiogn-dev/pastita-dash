## Problema — a cozinha zera ao tocar "Iniciar preparo"/"Pronto!"

`KdsPage` (`src/pages/kds/KdsPage.tsx`) é a tela fullscreen da cozinha. O cache de
pedidos (`rootStore.orders`) é **sempre chaveado pelo UUID da loja**: `setOrders`
normaliza slug→uuid por dentro (`resolveStoreKey`, `rootStore.ts:144-150`), e o
seletor de **exibição** da página já lê normalizado (`KdsPage.tsx:52`).

O caminho **otimista** do clique, porém, lia e gravava pela chave crua da rota:

```ts
const current = orders[storeId as string] || [];   // storeId é o SLUG
setOrders(storeId as string, current.map(...));
```

Mas `storeId` vem do `useParams` e a rota `/stores/:storeId/kds` carrega o **slug**
(`OrdersPage.tsx:782` e `DashboardPage.tsx:627` linkam com `storeSlug`). Logo
`orders[slug]` é um balde **sempre vazio** (tudo vive sob o UUID): `current` vira
`[]`, o `.map` continua `[]`, e `setOrders` normaliza slug→uuid e grava `[]` por
cima do balde real. O seletor de exibição então lê o UUID e encontra `[]` — ou
seja, **no instante em que o cozinheiro toca "Iniciar preparo" ou "Pronto!", o
quadro inteiro fica em branco** até um evento de WebSocket ou um refresh manual
repovoar o cache.

É exatamente a assimetria que o `OrdersPage` já tinha corrigido: lá o caminho
otimista usa `orders[resolveStoreKey(...)]` (`OrdersPage.tsx:538`); no KDS ficou
de fora.

## O que mudou

`src/pages/kds/KdsPage.tsx` (`handleAdvance`): a leitura e a escrita otimistas
passam a usar a **mesma chave normalizada** do seletor de exibição.

```ts
const { orders, setOrders, stores } = useRootStore.getState();
const key = resolveStoreKey(stores, storeId);
const current = orders[key] || [];
setOrders(key, current.map((o) => (o.id === order.id ? { ...o, status: next.status } : o)));
```

`resolveStoreKey` já estava importado (usado na linha 52). Sem mudança de rede, de
rota, de contrato de API nem de comportamento visual — só a chave do cache.

### Infra de teste

`jest.config.cjs`: `KdsPage` lê `import.meta.env` (base da API/WS para o tempo
real) e `src/pages/kds/` não estava na lista do `jestViteEnvTransform.cjs` — importar
a página num teste quebrava com "Cannot use 'import.meta' outside a module", o que
a mantinha intestável. Adicionada a entrada `'/src/pages/kds/(?!__tests__/)...'`,
no mesmo padrão já usado para `src/utils`, `src/services`, `src/components/maps` etc.
